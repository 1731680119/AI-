# 零基础维护手册

这份手册不要求你学过编程。目标不是让你一次记住所有代码，而是让你知道：项目由什么组成、问题应该去哪里找、修改后如何确认没有弄坏其他功能。

## 1. 先认识六个基本概念

### 1.1 文件和目录

“目录”就是文件夹。“项目根目录”指包含 `frontend`、`backend`、`README.md` 的 `origin resource` 文件夹。文档中的相对路径都从这里开始。

它的同级目录 `source` 是桌面端打包工程，装的是 Electron 外壳和安装包配置，不放业务代码。

### 1.2 前端

前端是界面上能看到和点击的部分，例如侧栏、消息气泡、输入框和设置弹窗。正式版里这些页面由 Electron 窗口显示，开发时则用浏览器打开，代码是同一份。本项目的前端使用 React 和 TypeScript：

- React 用“组件”拼页面。一个组件通常对应页面上的一块区域。
- TypeScript 是带数据类型检查的 JavaScript。它能在运行前发现字段拼错等问题。
- CSS 控制颜色、宽度、间距和响应式布局。

### 1.3 后端

后端是运行在本机的服务。它接收前端请求，读写数据库，调用 AI 接口，再把结果交还前端。本项目的后端使用 Python 和 FastAPI。

### 1.4 API

API 可以理解为前端和后端约定好的“窗口”。例如前端向 `/api/conversations` 请求会话列表，后端就返回会话数据。窗口地址、请求方式和数据字段必须两边一致。

### 1.5 数据库

数据库是有规则的数据文件。本项目使用 SQLite，所有会话、消息、设置和图片记录集中在一个 `chatbot.db` 文件里，位置见第 8 节。它不需要单独安装数据库软件。

### 1.6 端口

同一台电脑会同时运行很多网络服务，端口用来区分它们：

- `5180`：开发时的前端页面，访问地址是 `http://localhost:5180`。
- `8010`：开发时的后端接口，访问地址是 `http://127.0.0.1:8010`。

开发时页面把 `/api` 请求交给 Vite，Vite 再转发到 8010 端口，转发规则写在 `frontend/vite.config.ts`。

正式的桌面版不用这两个固定端口：Electron 主进程会给后端 exe 分配一个空闲端口，所以排查正式版问题时不要照抄 8010。

## 2. 日常操作要记住的四条命令

项目根目录有三个 `.bat` 脚本，双击即可：`setup.bat` 装依赖、`start.bat` 启动开发环境、`check.bat` 改完代码后检查。下面同时给出它们等价的手动命令，方便你在终端里单独执行某一步。前两条只在第一次使用、换电脑或依赖损坏时需要跑。

### 装后端依赖

```bat
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 装前端依赖

```bat
cd frontend
npm install
```

### 启动开发环境

要两个终端，一个跑后端，一个跑前端。前端启动后会自己打开 `http://localhost:5180`。

```bat
cd backend && .venv\Scripts\python.exe main.py
```

```bat
cd frontend && npm run dev
```

### 改完代码后检查

```bat
cd frontend && npm run build
python -m compileall -q -x "\.venv|data" backend
```

第一条检查 TypeScript 类型并生成正式版前端，第二条检查 Python 语法。两条都通过后，再到页面上做实际操作测试。

打安装包是另一套流程，步骤在 [README](../README.md) 的“打包安装包”一节。

## 3. 最安全的修改流程

1. 停止正在运行的前后端窗口。
2. 备份数据目录（位置见第 8 节）。
3. 一次只改一个目标，例如“修改发送按钮颜色”。
4. 运行第 2 节的两条检查命令。
5. 如果失败，从输出中第一条明确的错误开始看，不要只看最后一句“构建失败”。
6. 启动开发环境，在页面里验证相关功能。
7. 同时快速检查新建对话、发送短消息、设置弹窗和图片模式。
8. 确认正常后再进行下一个修改。

不要同时大改前端、后端和数据库。改动越小，出现问题时越容易定位。

## 6. 前端是怎样工作的

页面加载 `index.html` 后执行 `main.tsx`。`main.tsx` 把 `App` 放进页面。`App` 再根据当前模式显示聊天页或图片页。

组件不直接读数据库。组件通过 `useStore` 读取全站状态或执行动作；Store 再调用 `services/api`；API 模块向后端发送请求。

例如点击一个历史会话时：

1. `Sidebar.tsx` 调用 `selectConversation(id)`。
2. `useAppStore.ts` 先记录当前会话 ID。
3. Store 调用 `services/api/conversations.ts` 的 `getConversation`。
4. 后端返回整棵消息树。
5. Store 保存消息树。
6. `MessageList.tsx` 发现状态变化，自动重新显示消息。

这叫“单向数据流”：用户操作向下发出动作，数据返回后统一更新状态，组件再根据状态重新显示。

## 7. 后端是怎样工作的

开发时运行 `python main.py`：

1. `main.py` 加载 `.env`。
2. 创建 FastAPI 应用。
3. 将 `routers/__init__.py` 中列出的路由挂到应用。
4. 初始化 SQLite 表。
5. 在 8010 端口等待请求。

正式的桌面版走 `desktop_server.py`，由 Electron 主进程以 `chatbot-backend.exe --port <端口>` 启动，端口是动态分配的，其余流程一样。

路由文件只负责三件事：接收参数、调用数据库或服务函数、返回结果。复杂逻辑应放在 `database.py`、`llm.py`、`files.py` 或 `images.py`，不要全部塞回路由。

## 8. 数据保存在哪里

数据目录由 `CHATBOT_DATA_DIR` 环境变量决定，没设置时落在 `backend/data/`（见 `paths.py`）。因此有两个位置，别搞混：

- **正式桌面版**：`%LOCALAPPDATA%\AI Chatbot\data\`。Electron 主进程启动后端时会把 `CHATBOT_DATA_DIR` 指到这里。
- **开发模式**：`backend/data/`。直接跑 `python main.py` 时没有那个环境变量，就会用这个默认位置。

两边目录结构相同：

- `chatbot.db`：会话、消息、设置和图片历史记录。
- `uploads/`：聊天附件原文件。
- `images/`：生成或编辑后的图片。
- `logs/`：运行日志。
- `runtime/`：后端当前监听的服务地址。

所以在开发模式里测出来的对话不会出现在正式版里，反过来也一样。要改正式版的数据位置，改 `../source/desktop/main.cjs` 里传给后端的 `CHATBOT_DATA_DIR`；改动后原目录的数据不会自动跟过去，需要手动复制整个数据目录。

## 9. 备份和恢复

### 备份

1. 关闭应用。
2. 复制整个数据目录（正式版是 `%LOCALAPPDATA%\AI Chatbot\data\`）。
3. 给备份目录加日期，例如 `data-backup-2026-08-03`。

### 恢复

1. 关闭应用。
2. 把当前数据目录改名保留，不要直接永久删除。
3. 把备份复制回来并命名为 `data`。
4. 启动应用检查会话和图片。

不要在程序运行时替换 `chatbot.db`，否则可能得到未完成的数据库写入。

## 10. 配置和密钥

推荐直接在设置弹窗填写 API 信息。配置会写入本地数据库。桌面版还支持在设置里配置多个 API，一个失败会自动换下一个，这部分界面由 `../source/desktop/page-enhancements.js` 注入。

也可复制 `.env.example` 为 `.env`，填写 `OPENAI_API_KEY` 和 `OPENAI_BASE_URL`。只有数据库中尚无聊天密钥时，后端才会在启动时导入环境变量。

不要：

- 把真实密钥写进 `.env.example`。
- 把 `.env` 发给别人。
- 把 `chatbot.db` 提交到公共仓库。
- 在报错截图中暴露密钥或完整请求头。

## 11. 什么情况下需要同时修改前后端

只改文案、颜色、布局通常只动前端。

如果新增一个设置字段或一种数据字段，通常需要同步修改：

1. 前端 `types/` 中的数据类型。
2. 前端设置表单或功能组件。
3. 前端 `services/api/` 请求。
4. 后端路由的 Pydantic 请求模型。
5. 后端默认设置或数据库结构。
6. 实际使用这个字段的服务函数。

漏掉任何一层，都可能出现“页面能填但保存后消失”或“后端有字段但页面看不到”。

## 12. 修改完成的最低验收清单

- 第 2 节的两条检查命令都通过。
- 页面能打开，没有一直显示“等待后端”。
- 可以新建对话。
- “继续”“好的”等短消息显示正常。
- AI 回答能逐字出现，停止按钮有效。
- 历史会话可以切换。
- 设置弹窗左侧每个分类都能点开，切换分类后已填未保存的内容不丢。
- 设置保存后重新打开仍然存在。
- 浅色和深色主题正常。
- 图片历史能打开；如果有图片 API，再测试生成。
- 开发者工具 Console 没有新增红色错误（桌面版按 `Ctrl+Shift+I` 打开）。
