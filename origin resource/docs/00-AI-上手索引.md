# AI 上手索引（先读这一篇）

这篇是给 AI / 新维护者的入口。目标是**读文档而不是读源码**就能知道要改哪个文件、改动会牵连什么。

约 5400 行 Python + 7300 行前端 + 2400 行桌面端脚本，全读一遍要几十万 token。按下面的路由表只读需要的那几个文件。

## 0. 四条硬规则

1. **源码只在 `origin resource/`**。`../source/frontend/` 和 `../source/backend/` 是构建产物副本，改那里等于白改，下次构建就被覆盖。
2. **每次改完代码，必须把改动补进文档**，见 [08-变更记录.md](08-变更记录.md) 的“文档维护规范”。文档不更新，下一个 AI 就得重新读源码，这条是整套文档能省 token 的前提。
3. **本仓库是公开仓库，是开发目录的一份同步副本**。在安装目录（`AI Chatbot/important resource/`）里改完代码，必须把改动同步过来并写进 08 的变更记录，见 08 §3。
4. 改完至少跑一次检查：`cd frontend && npm run build`，以及 `python -m compileall -q -x "\.venv|data" backend`。

## 0.1 开工前先提问（用户不说也要做）

收到任何非平凡的开发任务时，先走这条流程，不要直接动手：

> 现在你来向我提问，每次只能提问一个问题，然后根据我的回答来继续提问，以此来对我的需求进行明确与完善。直到你有 95% 以上的把握理解了我的需求以后，说出你的理解，然后当我确认无误后再开始工作。

**一次只问一个问题**，拿到回答再问下一个；把握 95% 以上时先复述完整理解，用户确认后才改代码。纯查询类（「这个函数在哪」「解释这段」）可以跳过。

另一条常驻规矩：靠 `data/logs/diagnostics/未处理-…` 里的日志排查并修完问题后，**自己把该文件夹前缀改成「已处理」**，不用等用户提醒（见 07 §2.1）。

## 3. 最容易踩的坑（改之前看一眼）

- `.model-menu` 在 `frontend/src/styles/chat.css` 里是 `bottom: calc(100% + 6px)`，**向上弹出**，为贴在窗口底部的输入框设计。顶栏菜单复用这个 class 会被遮住，正确做法是在 `styles/shared-components.css` 加作用域覆盖（参考 `.export-select .model-menu`），**不要动 `.model-menu` 本身**。
- `shared-components.css` 的 `.field input:not([type='range']):not([type='radio'])` 是 `width: 100%`，**没有排除 checkbox**。在 `.field` 里放勾选框会被撑成整行、把旁边的文字挤没（模型选择器踩过）。同样在 `shared-components.css` 加作用域覆盖压回去（参考 `.model-picker-row label input`），别去动那条公共规则——很多输入框都靠它。
- 注入脚本靠 CSS 类名定位（例如 `.enh-settings-slot`、`.modal-footer .btn-primary`）。React 侧改结构类名必须同步改 `page-enhancements.js`，否则桌面端专属界面静默消失。
- 前端改完必须 `npm run build` 并把 `frontend/dist/` 同步到 `../source/frontend/`，否则安装包里还是旧界面。验证是否进包：直接 grep `../source/frontend/assets/*.css` 里的关键字符串。
- 用户数据在 `%LOCALAPPDATA%\AI Chatbot\data\`（可用 `CHATBOT_DATA_DIR` 改），不在仓库里。删仓库不会丢聊天记录，但改数据库结构要考虑老库的兼容。
- API Key 走设置页或 `.env`，**任何时候都不要写进代码、日志或提交**。`logging_config.py` 有脱敏（`redact:108`、`mask_secret:104`），新增日志字段要确认经过它。
- **`async def` 处理函数里不要直接调同步阻塞代码**（网络请求、大文件读写、CPU 密集解析），要套 `asyncio.to_thread`。`async def` 的函数体跑在事件循环**上**，阻塞它 = 那段时间**所有**请求都派发不出去，表现是「某个耗时操作进行中，整个界面全卡住、点了没反应」。漏了不报错，只会静默拖死后端。正确先例见 `routers/settings.py` 的搜索测试；1.2.22 修的两处是 `routers/images.py: edit_image` 和 `routers/uploads.py: save_upload`。判断方法和复现步骤见 [05-故障排查.md](05-故障排查.md) §21（要点：后端 `elapsed_ms` 很小而前端很大，就是这个坑，**不是**数据库锁）。
- 后端改完**必须重编 `chatbot-backend.exe`**（`source/backend/` 里只有这个 exe，Python 源码进不了安装包）。只改 `.py` 不重编的话，包能正常打出来、跑起来还是旧逻辑，**没有任何报错**。步骤见 [07-桌面端与打包.md](07-桌面端与打包.md)，坑的详情见 05 §10.2。
