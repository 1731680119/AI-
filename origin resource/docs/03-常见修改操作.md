# 常见修改操作

开始前先备份数据目录：正式桌面版在 `%LOCALAPPDATA%\AI Chatbot\data\`，开发模式在 `backend/data/`（详见[零基础维护手册](01-零基础维护手册.md)第 8 节）。每完成一个小修改都运行 `check.bat`，不要等多个问题混在一起再检查。

## 1. 修改页面文字

假设要把输入框提示“今天我能帮你什么？”改成“请输入问题”。

1. 在编辑器中全局搜索原文字。
2. 搜索结果会指向 `frontend/src/features/chat/components/Composer.tsx`。
3. 只修改 `placeholder` 引号中的文字。
4. 保存，运行 `check.bat`。
5. 启动页面，确认输入框为空时显示新文字。

同一段文字可能出现多次。根据文件路径和周围标签判断，不要使用不受控制的全局替换。

## 2. 修改颜色

全站颜色集中在 `frontend/src/styles/base.css` 开头的变量中。`:root` 是浅色主题，`:root[data-theme='dark']` 是深色主题。

例如 `--accent` 是主强调色。修改时必须分别检查浅色和深色。组件应优先使用变量：

```css
.example {
  color: var(--text);
  background: var(--bg-panel);
  border-color: var(--border);
}
```

不要在多个组件里重复写同一个十六进制颜色，否则更换主题时很难统一维护。

## 3. 修改尺寸、间距和换行

1. 在浏览器中按 `F12` 打开开发者工具。
2. 使用元素选择工具点中目标。
3. 查看它的 `class`，例如 `user-bubble`。
4. 在 `frontend/src/styles/` 全局搜索 `.user-bubble`。
5. 修改后同时测试普通桌面宽度和较窄窗口。

常见 CSS 含义：

| 属性 | 含义 |
|---|---|
| `width` | 固定或相对宽度 |
| `max-width` | 最大允许宽度 |
| `padding` | 内容与边框之间的内边距 |
| `margin` | 元素与外界的间距 |
| `gap` | Flex/Grid 子项之间的距离 |
| `display: flex` | 使用弹性布局 |
| `align-items` | 交叉方向对齐 |
| `justify-content` | 主方向对齐 |
| `white-space` | 空格和换行处理 |
| `word-break` | 长文字怎样断行 |
| `overflow` | 内容超出容器时怎样处理 |

短文本换行问题通常不是文字中真的有换行，而是父容器过窄。先检查元素和父元素的实际宽度，不要直接使用 `white-space: nowrap` 掩盖问题，因为那可能让长消息溢出。

## 4. 添加一个新的设置字段

以下以“是否显示思考过程”开关为例。一个完整设置要贯穿多层。

### 第一步：后端默认值

在 `backend/database.py` 的 `DEFAULT_SETTINGS` 增加：

```python
"show_thinking": True,
```

设置表使用键值存储，因此增加普通设置不需要修改 SQL 表结构。

### 第二步：后端请求模型

在 `backend/routers/settings.py` 的 `SettingsPatch` 增加：

```python
show_thinking: bool | None = None
```

如果漏掉这一步，前端发送的字段会被 Pydantic 忽略或拒绝。

### 第三步：前端类型

在 `frontend/src/types/index.ts` 的 `Settings` 增加：

```ts
show_thinking: boolean
```

### 第四步：设置界面

设置弹窗是左侧分类导航加右侧内容的分栏结构，分类清单是 `SettingsModal.tsx` 顶部的 `SECTIONS`：聊天、多 API、上下文、联网搜索、长期记忆、回答风格、提示词模板、附件、图片生成、诊断。所以加字段的第一件事是决定它属于哪一栏，把控件写进那一栏对应的分支里，而不是随手追加到文件末尾。

控件读取 `draft.show_thinking`，变化时调用：

```ts
patch({ show_thinking: e.target.checked })
```

`draft` 是打开弹窗时从设置拷出来的草稿，只有点“保存”才写回后端，因此切换分类不会丢掉已填未保存的内容。

两个改这个文件时容易踩的点：

- 带 `desktopOnly: true` 的分类（目前是“多 API”）只在 Electron 里出现，靠 `isDesktop()` 判断 `window.chatbotDesktop` 是否存在。浏览器里看不到它不是 bug。
- 文件里的 `.enh-settings-slot` 是给桌面端注入脚本预留的挂载点，`../source/desktop/page-enhancements.js` 靠这个类名找位置。不要改名或删掉，否则桌面版的多 API 列表会消失。

### 第五步：使用设置

在 `ThinkingBlock` 所在组件读取设置；为 `false` 时不显示该区域。不要只增加设置表单却不在实际功能中使用。

### 第六步：验证

保存设置、刷新页面、重新打开设置，确认值仍在；分别测试开启和关闭。

## 5. 增加一个普通后端接口

假设增加 `/api/health` 健康检查。

1. 在 `backend/routers/` 新建 `health.py`。
2. 创建 `APIRouter(prefix='/api', tags=['health'])`。
3. 使用 `@router.get('/health')` 定义函数。
4. 在 `backend/routers/__init__.py` 导入它。
5. 把它加入 `ALL_ROUTERS`。
6. 启动后访问 `http://127.0.0.1:8010/docs`，确认接口出现。
7. 如果前端要调用，在 `frontend/src/services/api/` 新建或选择对应模块。
8. 通过 `requestJson` 调用，不要在页面组件里直接散写 `fetch`。

路由只做输入验证和调度。可复用或较长的业务逻辑放到独立服务函数。

## 6. 增加一个新的页面功能

假设增加“知识库”模式：

1. 在 `frontend/src/features/knowledge/` 建目录。
2. 先创建一个页面组件和独立样式文件。
3. 在 `AppMode` 类型中加入 `'knowledge'`。
4. 在 Store 增加知识库所需状态和动作。
5. 在侧栏模式切换处加入按钮。
6. 在 `App.tsx` 根据 mode 显示知识库页面。
7. 如果需要后端，在 `backend/routers/knowledge.py` 新增路由并挂载。
8. 前端在 `services/api/knowledge.ts` 封装请求，并从 `index.ts` 导出。
9. 若有新数据表，在 `database.init_db()` 的 SQL 中使用 `CREATE TABLE IF NOT EXISTS`。
10. 在文档的目录、接口和数据字典中补充说明。

不要把整套知识库页面继续写进 `App.tsx`，也不要把它的所有样式放进 `base.css`。

## 7. 增加数据库字段

修改数据库比修改普通设置风险更高。先备份。

SQLite 的 `CREATE TABLE IF NOT EXISTS` 不会给已经存在的表自动增加新列。需要显式迁移，例如：

1. 使用 `PRAGMA table_info(table_name)` 查看列是否存在。
2. 不存在时执行 `ALTER TABLE table_name ADD COLUMN ...`。
3. 给旧行设计合理默认值。
4. 所有读取函数和返回字典同步字段。
5. 前端类型同步字段。

不要通过删除 `chatbot.db` 来“解决”字段问题，那会清空历史数据。

## 8. 增加一种附件格式

假设支持 `.xlsx`：

1. 在 `frontend/src/features/chat/components/Composer.tsx` 的文件 `accept` 中加入扩展名。
2. 在 `backend/files.py` 增加解析依赖和解析函数。
3. 在 `save_upload` 中根据扩展名设置 `kind` 和 `text_content`。
4. 更新 `Attachment.kind` 类型；或决定继续归类为 `file`。
5. 在 `backend/requirements.txt` 增加依赖。
6. 重新运行 `setup.bat` 安装新增依赖。
7. 用小文件、空文件、超大文件和包含中文的文件测试。

不要信任扩展名代表的内容；解析函数必须捕获异常并返回可理解的错误。

## 9. 更换聊天接口或模型

如果新服务兼容 OpenAI Chat Completions：

1. 通常只需在设置中修改 Base URL、API Key 和模型名。
2. `backend/llm.py` 的 `build_client` 会使用这些配置。
3. 流式解析已兼容 `reasoning_content` 和 `<think>` 标签。

如果新服务不兼容 OpenAI：

1. 不要在路由里硬塞供应商判断。
2. 为新供应商编写独立适配函数，统一产出 `thinking`、`content`、`error`、`done` 事件。
3. 路由和前端 SSE 协议尽量保持不变。
4. 为断网、空响应、非标准片段和中途异常做测试。

## 10. 修改会话标题

标题在首条消息回答结束后由 `backend/routers/chat.py` 的 `first_message_title()` 就地生成：
压掉空白后取前 20 字，超了补 `...`，然后 `rename_conversation` 并发一个 `title` 事件。

**不要再加回「调模型生成标题」那套**（原来的 `llm.generate_title` 已删）：那一步要额外发一次
请求，还会让首条回答结束后干等最长 15 秒，而它失败时的降级结果和现在这个完全一样。

改动后测试：中文短问题、很长的首条问题、多行提问（换行要被压成空格）。

## 11. 修改图片生成参数

默认模型、尺寸和质量在 `backend/database.py` 的 `DEFAULT_SETTINGS`。设置页面字段在 `SettingsModal.tsx`，提交参数在 `ImagePage.tsx`，后端校验和调用在 `routers/images.py` 与 `images.py`。

增加一个新参数时，这几层都要同步。先确认图片服务真的支持该参数；OpenAI 兼容并不代表所有图片接口的参数完全一致。

## 12. 修改依赖

### 前端依赖

在 `frontend` 目录运行 `npm install 包名`。这会同时更新 `package.json` 和 `package-lock.json`。不要只手工改其中一个。

### 后端依赖

开发依赖范围写入 `backend/requirements.txt`。打包安装版需要可复现版本时，再同步 `requirements-installer.txt`。

新增依赖后：

1. 重新运行 `setup.bat`，让 `backend/.venv` 装上新依赖。
2. 运行 `check.bat`。
3. 如果要出安装包，打包用的 `.buildvenv` 是另一个环境，必须按 `requirements-installer.txt` 单独装一遍，否则 exe 里还是缺这个包。
4. 在一台没有旧缓存的环境验证安装。

## 13. 重构时的边界规则

- 页面组件不直接操作 SQLite。
- 后端不返回磁盘任意绝对路径。
- React 组件不散写重复 API 地址。
- 路由不堆积模型流解析或 SQL。
- 所有数据目录从 `paths.py` 获取。
- 新类型集中放 `types/`，不要在多个组件重复声明同一数据结构。
- 新样式按功能放置，并从 `styles/index.css` 引入。
- 移动文件后先修复引用并运行检查，再继续改逻辑。
- 注入脚本依赖的类名（例如 `.enh-settings-slot`）属于对外契约，改名要同步改 `../source/desktop/page-enhancements.js`。
- 前端改完只在开发模式生效。要让安装包也变，必须 `npm run build` 并把 `frontend/dist/` 同步到 `../source/frontend/`，步骤见 [README](../README.md) 的“打包安装包”。
