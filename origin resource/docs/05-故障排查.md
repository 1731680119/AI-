# 故障排查

排错时先记录“做了什么、预期什么、实际什么”，再看错误信息。不要看到页面异常就先删除数据库或重新安装全部软件。

## 1. 页面打不开

### `http://localhost:5180` 无法访问

1. 查看“AI助手-前端”窗口是否仍在运行。
2. 查看是否提示 `npm` 找不到；若是，安装 Node.js 并重新打开终端。
3. 确认已运行 `setup.bat`，且 `frontend/node_modules/` 存在。
4. 端口可能被占用。前端窗口通常会显示它改用的新端口，按显示地址访问。

## 2. 一直显示“正在等待后端服务启动”

1. 查看“AI助手-后端”窗口第一条错误。
2. 访问 `http://127.0.0.1:8010/docs`。能打开说明后端已启动。
3. 运行 `check.bat` 检查 Python 语法。
4. 如果提示缺少模块，重新运行 `setup.bat`。
5. 如果 8010 被占用，在 PowerShell 运行：

```powershell
Get-NetTCPConnection -LocalPort 8010 -State Listen
```

先确认占用它的是哪个程序，不要直接结束不认识的系统进程。

## 3. 设置或会话列表请求失败

打开浏览器开发者工具：

1. 按 `F12`。
2. 查看 `Console` 是否有红色错误。
3. 打开 `Network`，刷新页面。
4. 找到失败的 `/api/...` 请求。
5. 查看 Status 和 Response。

如果返回 HTML 而不是 JSON，通常是 URL 转发或后端地址错误。检查 `frontend/vite.config.ts` 中目标是否仍为 `http://127.0.0.1:8010`。

## 4. 发送后没有回答

依次检查：

- 设置中的聊天 Base URL、API Key、默认模型是否正确。
- 模型名是否确实存在于服务商账户。
- Base URL 是否需要以 `/v1` 结尾，以服务商文档为准。
- 错误横幅是否显示余额、权限、限流或参数错误。
- 后端是否能访问外部模型服务。

模型接口失败通常不会损坏本地数据库，但可能留下空回答节点。重新打开会话后以服务器保存内容为准。

## 5. 回答不是流式，最后一次性出现

可能原因：

- 上游代理缓存了 SSE。
- 模型服务虽然接受 `stream=true`，但实际不分片。
- 反向代理没有关闭响应缓冲。
- `frontend/src/services/api/chat.ts` 的事件分隔处理被修改。

先直接观察 `/api/chat` 响应是否持续出现多个 `data:` 块，再判断问题在上游、后端还是前端。

## 6. 思考内容混进正文

`backend/llm.py` 支持两种格式：`reasoning_content` 字段和 `<think>...</think>` 标签。新服务如果使用另一种字段，需要在这里增加适配，但仍统一产出 `thinking` 事件。

检查原始流时注意隐藏 API 密钥和私人对话内容。

## 7. 历史对话消失

先不要创建大量新会话。检查：

1. 当前实际数据目录是否被 `.env` 的 `CHATBOT_DATA_DIR` 改过。
2. `backend/data/chatbot.db` 是否存在且大小不为 0。
3. 是否从另一份项目目录启动了程序。
4. 是否刚替换过数据库文件。

历史数据通常还在另一个目录。找到多个 `chatbot.db` 时，先分别复制备份，不要靠文件名猜测后覆盖。

## 8. 数据库报 locked

SQLite 同一时间只允许有限的写操作。常见原因是启动了多个后端，或另一个工具长时间打开数据库事务。

1. 关闭所有本项目后端窗口。
2. 关闭 SQLite 查看工具。
3. 等待几秒再启动一次。
4. 仍有问题时，备份数据库后再进一步检查。

## 9. 上传文件失败

- 超过 30MB 会返回 413。
- PDF 或 Word 损坏时，附件可能上传成功但 `text_content` 是解析错误说明。
- 老式 `.doc` 并不是标准 `.docx`，当前解析库可能无法读取。
- 图片模式不常见时会转为 JPEG 预览；原文件仍保留。

解析逻辑位于 `backend/files.py`。先用一个很小、内容简单的文件验证基础流程。

## 10. 图片生成失败

图片功能有独立的 Base URL、API Key 和模型设置。聊天能用不代表图片配置正确。

检查服务是否支持：

- `images.generate` 或 `images.edit`。
- 当前尺寸字符串。
- 质量参数。
- 一次生成多张图片。
- 返回 `b64_json` 或可下载 `url`。

后端错误横幅会显示上游异常。不要把含密钥的完整请求记录发到公共渠道。

## 11. 联网搜索不工作

联网搜索不再依赖浏览器扩展。它由后端调用 DeepSeek Responses API 的服务端内置 `web_search` 工具完成，所以排查方向是接口配置，不是浏览器。

1. 确认设置的“联网搜索”里已经填好搜索专用的接口地址、API Key 和模型，并且保存过。这三项和主对话模型是两组独立配置，主对话能用不代表搜索能用。
2. 搜索接口必须是支持 `/responses` 且提供内置 `web_search` 的服务。填一个只有 `/chat/completions` 的地址会失败，因为服务端内置搜索只挂在 `/responses` 上。
3. 打开日志查看 `backend.web_search` 的记录。请求被拒绝会写下状态码和响应片段，密钥在日志里是打码的，可以安全贴出来。
4. 返回 401 或 403 说明密钥无效或没有搜索权限；返回 404 通常是地址少写或多写了 `/v1`。

模型自己决定要不要搜。问题明显不需要检索时它不会调用工具，这不是故障。想确认链路是否通，直接问一个必须查实时信息的问题。

## 12. 搜索结果里的来源很少或没有来源

来源来自搜索服务实际打开过的网页，数量由上游决定，本地无法强制。如果结论有内容但来源为空，通常是上游只做了检索没有逐页打开。

搜索结果始终按不可信内容处理，只作为参考材料，不会当成指令执行。如果回答里出现明显来自网页的可疑指令，那是提示注入，应作为 bug 记录下来。

## 13. 样式修改没有效果

1. 确认修改的是 `frontend/src/styles/` 中被 `index.css` 导入的文件。
2. 全局搜索同名选择器，后导入规则可能覆盖前面。
3. 查看浏览器开发者工具中该规则是否被划掉。
4. 强制刷新页面。
5. 如果看的是真实构建文件，重新运行构建。

不要直接编辑 `frontend/dist/assets/`。那里是自动生成文件，下次构建会覆盖。

## 14. TypeScript 构建失败

常见信息：

- `Cannot find module`：文件移动后 import 路径错误，或依赖未安装。
- `Property ... does not exist`：类型中没有该字段，检查 `types/index.ts`。
- `Type ... is not assignable`：传入值的类型与目标不一致。
- `declared but its value is never read`：导入或变量已无用途，应删除。

从第一条错误处理。后面的很多错误可能只是第一处导致的连锁反应。

## 15. Python 启动失败

常见信息：

- `ModuleNotFoundError`：依赖未装或 import 路径错误。
- `SyntaxError`：错误行附近少了引号、括号或缩进不一致。
- `IndentationError`：Python 缩进错误；统一使用 4 个空格。
- `Address already in use`：端口已占用。

运行 `check.bat` 可以提前发现语法错误，但不会调用真实模型接口。

## 16. 修改后页面完全空白

通常是前端运行时异常：

1. 打开 Console 看第一条红色错误。
2. 检查最近移动文件的 import。
3. 检查组件是否在数据为 `null` 时仍直接读取字段。
4. 检查 Hook 是否被条件调用；React Hook 必须在组件顶层稳定调用。
5. 退回最近一个小改动，而不是同时改更多地方尝试碰运气。

## 17. 寻求帮助时应提供什么

提供：

- 操作系统和浏览器版本。
- 复现步骤。
- 预期结果与实际结果。
- `check.bat` 第一条错误。
- 浏览器 Console 的相关错误。
- 后端窗口相关错误。
- 最近改过的文件列表。

先删除或遮盖 API Key、私人消息、上传文档内容和本机用户名路径。
