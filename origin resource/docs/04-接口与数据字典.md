# 接口与数据字典

后端启动后，可在 `http://127.0.0.1:8010/docs` 查看 FastAPI 自动生成的交互文档。本篇用于解释接口之间的关系和主要字段。

## 1. HTTP 基础

| 方法 | 常见用途 |
|---|---|
| `GET` | 读取数据，不应修改数据 |
| `POST` | 创建数据或发起任务 |
| `PUT` | 更新已有数据 |
| `DELETE` | 删除数据 |

成功通常返回 2xx。常见错误：400 表示参数或配置问题，404 表示记录不存在，413 表示文件过大，500 表示服务内部或上游 API 出错。

## 2. API 清单

### 设置

| 方法和路径 | 作用 | 前端函数 | 后端文件 |
|---|---|---|---|
| `GET /api/settings` | 读取完整设置 | `fetchSettings` | `routers/settings.py` |
| `PUT /api/settings` | 更新部分或全部设置 | `saveSettings` | `routers/settings.py` |
| `POST /api/settings/search-test` | 用给定的一套搜索配置真跑一次检索，返回是否可用、实际命中的接口地址与来源 | `testSearchProvider` | `routers/settings.py` |
| `POST /api/settings/model-list` | 用给定的地址和密钥读取上游模型清单，供设置页勾选。只读清单，不产生调用费用 | `listRemoteModels` | `routers/settings.py`、`model_probe.py` |
| `POST /api/settings/model-test` | 对单个模型发一次极短请求（`max_tokens=16`），确认它真的调得动 | `testRemoteModel` | `routers/settings.py`、`model_probe.py` |

这三个检测接口都直接收 `base_url`／`api_key` 字段而不是读设置，因此在设置页改完、还没点保存时就能测。地址带不带 `/v1` 都行，后端按候选路径依次尝试（`model_probe.py:_candidates`、`web_search.py`）。

判「路径不对、换下一个候选」的状态码有两套：读清单用 `_PATH_MISMATCH_CODES = {403, 404, 405, 501}`，发对话用 `_CHAT_MISMATCH_CODES = {404, 405, 501}`。区别在 403——`/chat/completions` 的 403 通常是「当前分组没有这个模型的渠道」，是上游的真实答复，直接透传比换个路径再撞一次 404 有用得多。另外 HTTP 200 但 `Content-Type` 是 `text/html` 也算路径不对（撞上了中转站的管理后台页面）。

### 代码执行

| 方法和路径 | 作用 |
|---|---|
| `POST /api/code-exec/decision` | 回应一次执行请求：批准或拒绝 |
| `POST /api/code-exec/revoke-trust` | 撤销此前授予的信任 |

注意路径是连字符 `code-exec`，不是下划线（`routers/code_exec.py:12`）。

代码本身不通过这两个接口提交。模型调用 `run_code` 工具后，后端在 `code_exec.py` 里静态检查并挂起等待（`_wait_for_decision:184`，超时 `DECISION_TIMEOUT_SECONDS = 120`），前端弹授权框，用户的选择通过 `/decision` 回传，再由子进程隔离执行（`run_subprocess:250`，超时 15 秒，输出上限 100KB）。

默认关闭，是风险最高的开关。改动前先想清楚执行环境的边界：白名单 `ALLOWED_MODULES:38`、禁用名 `BANNED_NAMES:48`。

### 图片

| 方法和路径 | 作用 |
|---|---|
| `GET /api/images` | 图片任务历史 |
| `POST /api/images/generate` | 文生图 |
| `POST /api/images/edit` | 上传图片并编辑 |
| `DELETE /api/images/{id}` | 删除记录和对应文件 |
| `GET /api/images/file/{name}` | 读取或下载图片文件 |
| `GET /api/images/export/formats` | 当前后端**真能编码**的导出格式清单 |
| `POST /api/images/export` | 把某张已保存的图片转成指定格式，直接返回二进制 |

#### 导出格式与参数（1.2.12 起）

`GET /api/images/export/formats` 返回 `{ "formats": [...] }`，每项字段：

| 字段 | 说明 |
|---|---|
| `key` | 传给 `POST /api/images/export` 的 `format` 值 |
| `label` / `ext` / `mime` | 界面显示名、扩展名、MIME |
| `alpha` | 该格式是否保留透明通道；`false` 时后端会用 `background` 把透明处填掉 |
| `quality` / `dpi` / `compression` | 布尔，表示这个格式吃不吃对应参数——前端据此显示/隐藏控件 |
| `note` | 一句话提示（如 ICO 上限 256px） |

**清单是运行时探测出来的**（`image_export.available_formats()` 逐格式试存一张 2×2 图，
带 `lru_cache`），不是写死的常量。缺编码器的格式会直接从清单里消失，不要在前端硬编码格式列表。

`POST /api/images/export` 请求体（`ExportBody`）：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `name` | string | — | `user-data/images/` 下的文件名，服务端会 `os.path.basename` 去掉路径 |
| `format` | string | — | 上面的 `key` |
| `quality` | int | 92 | JPEG/WEBP/HEIC/AVIF 有效；WEBP 传 100 走无损 |
| `tiff_compression` | string | `lzw` | `none` / `lzw` / `deflate` |
| `dpi` | int | 96 | 写进元数据；PDF 走 `resolution` 而不是 `dpi` |
| `background` | string | `#FFFFFF` | `alpha=false` 的格式用它拍平透明底 |
| `width` / `height` | int，可空 | null | 只给一个则按比例；上限 `MAX_EDGE = 8192` |

响应是二进制流，文件名在 `Content-Disposition` 里，**同时给了 ASCII 的 `filename=` 和
RFC 5987 的 `filename*=UTF-8''`**——中文提示词生成的名字靠后者。前端用
`services/api/http.ts` 的 `requestBlob()` 解析。参数不合法返回 400（`ExportError`），
转换本身失败返回 500。

## 3. 前端主要数据类型

### Attachment

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 上传时生成的唯一 ID |
| `name` | string | 用户原文件名 |
| `kind` | image/pdf/docx/text/file | 解析分类 |
| `stored_name` | string? | 磁盘保存名 |
| `size` | number? | 字节数 |
| `preview` | string? | 图片 data URL |
| `text_content` | string? | 文档提取文字 |

`preview` 和 `text_content` 可能很大。页面列表不要无必要地复制或打印完整值。

### Message

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 消息唯一 ID |
| `parent_id` | string/null | 父消息，用来形成分支树 |
| `role` | user/assistant | 消息角色 |
| `content` | string | 可见正文 |
| `thinking` | string/null | 模型思考内容 |
| `model` | string/null | 生成回答的模型 |
| `attachments` | Attachment[] | 用户附件 |
| `tool_calls` | ToolCall[]/undefined | 本条回答用到的工具及其展示数据 |
| `created_at` | string | 创建时间 |
| `streaming` | boolean? | 仅前端：是否正在生成 |
| `thinkingOpen` | boolean? | 仅前端：思考区是否展开 |

### ConversationMeta

侧栏使用的轻量会话信息：`id`、`title`、`created_at`、`updated_at`、`pinned`。

### ConversationTree

包含会话信息、`active_leaf_id` 和 `messages` 全部节点。它不是只返回当前路径，因为分支导航需要知道同一父节点下的兄弟消息。

### Settings

| 字段 | 说明 |
|---|---|
| `base_url` | 聊天 API 基础地址 |
| `api_key` | 聊天 API 密钥 |
| `models` | 前端模型下拉列表。**顺序有意义**：输入框上方的模型菜单可以拖动排序，结果就写回这个数组（1.2.14 起，见 07 §4.1） |
| `default_model` | 默认聊天模型 |
| `system_prompt` | 每次聊天上下文开头的系统提示 |
| `temperature` | 输出随机程度 |
| `max_tokens` | 最大输出 token 数 |
| `theme` | light 或 dark |
| `default_thinking` | 默认思考档位：auto/minimal/low/medium/high |
| `search_providers` | 联网搜索的配置列表，每项含 `id`/`name`/`base_url`/`api_key`/`model`/`max_output_tokens`。可以官方直连和各家中转站各存一条 |
| `search_provider_id` | 当前使用的那套搜索配置 id。调用失败不会自动切到别的配置，避免在不知情的情况下换一家继续花钱 |
| `image_base_url` | 图片 API 基础地址 |
| `image_api_key` | 图片 API 密钥 |
| `image_model` | 图片模型 |
| `image_size` | 图片尺寸 |
| `image_quality` | 图片质量 |

旧版本的搜索配置是 `search_base_url`／`search_api_key`／`search_model`／`search_max_output_tokens` 四个平铺字段，只能配一套。`database.py:get_settings` 在首次读取时会把它们迁成 `search_providers` 列表的第一条并从库里删掉，老用户升级后不用重填。

### ImageRecord

代表一次图片任务，不一定只包含一张图。`mode` 为 `generate` 或 `edit`，`files` 是结果文件名数组。

### UpdateState（桌面端专有，`hooks/useUpdateState.ts`）

主进程 `updater.cjs` 通过 `desktop:update-state` 广播过来的整包状态，前端不做增量合并。

| 字段 | 类型 | 说明 |
|---|---|---|
| `status` | idle/checking/available/not-available/downloading/downloaded/error/disabled | 浏览器里没有桥，恒为 `disabled` |
| `currentVersion` / `version` | string | 当前版本 / 查到的新版本 |
| `releaseNotes` / `releaseDate` | string | Release 正文（按纯文本渲染）与发布时间 |
| `percent` / `transferred` / `total` / `bytesPerSecond` | number | 下载进度 |
| `error` | string | 失败原因。后台自动检查失败不写这里，只回 `idle` |
| `checkedAt` | number | 上次检查的时间戳 |
| `channel` | string | 1.2.14 新增。本次是走哪条线路连上的：`直连` / `DoH 解析直连` / `镜像 xxx` / `系统代理 x.x.x.x:p` |

### 桌面端本地设置（`user-data/desktop-settings.json`）

后端库里没有这些，它只存在于本地 JSON（1.2.8 起放在 `data/` 子目录，见 10 §②-b）。
`enhancements` 一节由注入脚本的设置面板维护：

| 字段 | 类型 | 说明 |
|---|---|---|
| `apiList` | 数组 | 多 API 渠道列表，`apiKey` **明文存储**。顺序可拖动调整 |
| `updateProxy` | string | 1.2.14 新增。更新用的 HTTP 代理，写 `host:port` 或 `http://host:port`。**留空即自动探测系统代理**，不填是常态 |

`updateProxy` 只在检查更新和下载更新时生效，用完立刻还原（07 §5.1），不会影响应用里的其它网络请求，也不改动系统网络设置。

## 4. `/api/chat` 请求字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `conversation_id` | 是 | 目标会话 |
| `content` | 否 | 用户文字，重新生成时可为空 |
| `attachments` | 否 | 已上传附件 |
| `model` | 否 | 不传则使用默认模型 |
| `parent_id` | 否 | 编辑重发时指定父节点 |
| `regenerate_from` | 否 | 重新生成时指定旧回答 ID |
| `continue_from` | 否 | 继续生成：续写进这条已有回答，不另起一条 |
| `thinking` | 否 | 本次的思考档位，不传就用设置里的默认档位 |

不要同时随意使用 `parent_id` 和 `regenerate_from`。前者创建新的用户分支，后者创建新的回答分支。`continue_from` 又不一样：它不新建任何节点，而是把内容追加进原来那条回答，所以三个字段一次只该用一个。

## 5. 数据库表

数据库初始化 SQL 位于 `backend/database.py`。

### conversations

| 列 | 说明 |
|---|---|
| `id` | 会话 UUID，主键 |
| `title` | 标题 |
| `created_at` | 创建时间 |
| `updated_at` | 最后更新时间，用于排序 |
| `active_leaf_id` | 当前分支最后消息 |
| `pinned` | 置顶标记，当前界面尚未提供置顶操作 |
| `project_id` | 所属项目，可为空 |
| `style_id` | 会话选定的回答风格，可为空 |

`project_id` 和 `style_id` 是后加的列，用 `ALTER TABLE` 补上，没有外键约束——SQLite 的 `ALTER TABLE` 无法追加带级联的外键。

### messages

| 列 | 说明 |
|---|---|
| `id` | 消息 UUID，主键 |
| `conversation_id` | 所属会话，删除会话时级联删除 |
| `parent_id` | 父消息 ID |
| `role` | user 或 assistant |
| `content` | 正文 |
| `thinking` | 思考内容 |
| `model` | 回答模型 |
| `attachments` | JSON 字符串 |
| `tool_calls` | 工具调用记录 JSON：搜索关键词、来源、代码执行结果 |
| `created_at` | 创建时间 |

`conversation_id` 和 `parent_id` 上有索引，用来加速读取会话和查找分支。

### settings

通用键值表。`key` 是设置名，`value` 是 JSON 字符串。默认值不一定实际写入表；`get_settings()` 会把代码中的默认值与数据库值合并。

### images

保存图片任务的提示词、模型、尺寸、质量、源图片名、结果文件名数组和创建时间。真实图片不放进数据库，只放文件名。`reference_names` 和 `reference_notes` 是后加的列，保存参考图信息。

### projects

保存项目的名称、描述、项目说明和时间。`instructions` 是项目级系统提示词，会话属于某个项目时拼进请求。

### memories

长期记忆表：`content` 是记忆正文，`source_conversation_id` 记下它来自哪次对话，方便回溯。

### context_summaries

上下文自动压缩的结果。`covered_until_message_id` 标记这条摘要覆盖到哪条消息为止，`original_chars` 和 `summary_chars` 用来在界面上显示压缩比。会话删除时级联删除。

## 6. 数据一致性规则

- 每条消息必须属于一个存在的会话。
- 删除会话会删除其全部消息。
- `active_leaf_id` 应指向本会话中的消息。
- 图片记录中的文件名应存在于图片目录；删除记录时同步删除文件。
- 设置读取永远与 `DEFAULT_SETTINGS` 合并，保证旧数据库也能获得新默认字段。
- API 密钥属于敏感数据，不应出现在日志、文档示例或代码仓库中。
